## Obsidian → Quartz 同步脚本配置

### 背景
用户（lawsam）需要配置一个同步脚本，将 Obsidian vault 中的 Leetcode 文件夹同步到 Quartz 的 content 目录，然后推送到 GitHub。

### 关键发现
- 源路径 `E:\Documents\Obsidian_\Cpp\Leetcode` 是符号链接，真实数据在 `E:\Documents\Obsidian\Leetcode`（373 个文件，含中文文件名）
- Quartz 项目 Git remote: `origin → git@github.com:lawsums/Quartz_base1.git`，分支 `v5`
- `npx quartz sync --no-pull` 内部执行 git add/commit/push，不需要脚本重复 git 操作
- 在 WorkBuddy 沙箱中 `npx` 无法访问 `G:\MyPath\Nodejs\node_cache`，改用 `node ./quartz/bootstrap-cli.mjs sync --no-pull` 直接运行

### 完成内容
1. 编辑 `.gitignore`：追加 `scripts/` 和 `*.log` 规则
2. 创建 `scripts/sync-leetcode.sh`：使用 robocopy /MIR 镜像同步 + npx quartz sync 推送
3. 预演测试（robocopy /L）：373 文件，372 复制，1 跳过，无失败
4. 首次运行成功：文件复制、git commit（ccb4176）、push 到 GitHub v5 分支

### 技术要点
- robocopy 退出码 0-7 = 成功，8+ = 错误，不能用 `set -e`
- 排除规则：`/XF *.swp *.swo /XD .obsidian .git`
- 无变更检测：`git status --porcelain` 为空时跳过 sync
- 后续可配置 Windows 任务计划程序实现定时自动同步

### 修复：Templater 模板文件导致 build 失败
- 问题：`1.md`、`2.md`、`3.md` 是 Obsidian Templater 模板文件，YAML frontmatter 内含 `<%* ... _%>` JavaScript 代码，Quartz 解析 YAML 报错
- 修复：robocopy 排除 `/XF` 增加 `1.md 2.md 3.md`，并从 content/Leetcode/ 删除已复制的副本
- 修复后 build 成功：154 文件处理完成，输出 716 HTML 文件
- 注意：build 时会有大量 "Skipping circular transclusion" 警告，是 `![[file.cpp]]` 嵌入同名文件导致的，无害
