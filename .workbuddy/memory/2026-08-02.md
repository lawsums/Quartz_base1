## 修复番剧库/游戏库页面两个问题

### 1. 番剧更新后页面不刷新（JSON 浏览器缓存）
- 原因：`project-query.js` 的 `fetch("/static/projects-index.json")` 被浏览器缓存
- 修复：fetch 添加 `?v=timestamp` cache-busting 参数 + `{ cache: "no-cache" }`

### 2. 图片加载慢/不显示
- 原因1：Bangumi CDN 图片 URL 为 HTTP，在 HTTPS 站点上被混合内容策略拦截
- 修复1：generate-projects.js 的 extractCoverUrl() 强制 HTTP→HTTPS；project-query.js 渲染时也做 fallback 转换
- 原因2：图片加载失败时显示空白
- 修复2：添加 onerror fallback，加载失败时显示标题文字；添加 `decoding="async"` 异步解码
- 重新生成了 projects-index.json，59 个条目全部 HTTPS 封面

## 封面图片本地缓存系统
- 需求：远程图片（lain.bgm.tv）加载慢，希望下载到本地统一用本地路径
- 创建了 `scripts/cache-covers.js`：
  - 读取 projects-index.json → 用 curl 下载远程封面到 `quartz/static/covers/`
  - 文件命名：URL 的 MD5 哈希前16位 + 原始扩展名
  - 增量模式：已下载的图片跳过（检查 existsSync）
  - 下载失败保留远程 URL 作为 fallback
  - 并发5个，用 curl（走系统代理）而非 Node.js fetch（不走代理）
- 集成到工作流：
  - sync-obsidian.sh 新增步骤 [4/6]：generate-projects.js 之后运行 cache-covers.js
  - package.json prebuild 新增 `npm run cache-covers`
- 首次运行结果：58/59 下载成功（27MB），1个 RAWG 图片因 SSL 握手失败保留远程 URL
- JSON 中 cover 字段从 `https://lain.bgm.tv/...` 替换为 `/static/covers/{hash}.jpg`

## 修复番剧库页面加载白屏
- 问题：页面打开后只有标题（在看/想看/已看），卡片区域长时间空白，用户体验差
- 原因1：`<script defer>` 导致 JS 在 DOM 解析完成后才执行，fetch JSON 有延迟
- 修复1：Head.tsx 添加 `<link rel="preload" href="/static/projects-index.json" as="fetch">` 提前加载 JSON
- 原因2：fetch 期间没有任何加载提示，用户以为页面坏了
- 修复2：project-query.js 添加 `showLoading()` 函数，init() 时先显示旋转加载动画
- 修复3：project-styles.css 添加 `.project-grid-loading` 和 `.project-grid-spinner` 样式
- build 验证通过，public/static/covers/ 58 个文件已复制

## 番剧库渲染方案对比 → 最终采用内嵌JSON
- 创建了三个对比页面来测试加载速度：
  - 番剧库：原始方案，JS fetch JSON（最慢）
  - 番剧库2：内嵌 JSON，JS 从 DOM 读取（最快）
  - 番剧库3：预渲染静态 HTML（中间）
- 用户确认：内嵌 JSON 比其他两个快很多
- 最终方案：
  - 番剧库.md 改用 data-project-query-inline + 内嵌 `<script id="projects-data">` 
  - 新文件 `quartz/static/project-query-inline.js`：从 DOM 读 JSON 而非 fetch
  - generate-anime-pages.js 改为生成番剧库.md（替换 PLACEHOLDER_JSON 占位符）
  - 删除番剧库2.md 和番剧库3.md（测试页面）
  - sync-obsidian.sh 回到 6 步工作流
- 原理：构建时将 JSON 注入页面，浏览器打开瞬间 JS 就能渲染，零网络请求延迟
